## Next.js port (global)

**55. State panel mechanism** — a client context provider holds the state bag; the list of toggles per page-type comes from a static map keyed off the route registry. _Block bodies read state values to decide what they render, so a provider is required regardless; pages registering states separately would duplicate that channel._ → Set aside: pages self-registering with the panel — simpler API, but two channels for the same values.

**56. Real nested URLs** — App Router paths replace legacy flat hashes. `/` is Home; the wireframe index lives at `/wireframes`. _Real routes with shareable URLs; the iframe hash problem decision 17 solved no longer applies._ → Set aside: keeping flat hash-style paths — would fight the App Router and lose readable URLs.

**57. Legacy border weights kept** — 2px on header rule, primary buttons and active tabs; 3px on C6, N8, AB2 callouts; 2px dashed on stubs and the state panel. _Weight is the legacy file's only emphasis signal; flattening to 1px would lose C6's "visually set-apart" treatment._ → Set aside: strict 1px everywhere — obeys the original AGENTS constraint but makes callouts indistinguishable from prose blocks.

**58. Type scale collapsed** — legacy 10/11/12px → `text-xs`; 13/14px → `text-sm`; body base `text-sm`. `--fill:#eee` → `neutral-200`; `--soft:#666` → `neutral-500`. _Maps the legacy palette onto the permitted Tailwind set without inventing arbitrary sizes._ → Set aside: preserving exact pixel sizes — outside the permitted utility set.

**59. Square timeline markers** — S1 programme timeline uses 2.5×2.5px square markers instead of the legacy round dots. _The permitted Tailwind set excludes `rounded-*`; a square marker preserves the sequence cue without breaking the lo-fi constraint._ → Set aside: round dots via inline styles — would work but adds a one-off exception outside the utility set.

**60. Single client boundary at ProgramPage** — wireframe state (`closed`, `offered`) is read once in `ProgramPage` and passed down as props; block components stay server-renderable except where a child primitive requires interactivity (`Accordion`). _One boundary is easier to trace than scattering `"use client"` across C7 and S3._ → Set aside: per-block client components — each block self-contained, but duplicates the state channel.

**61. C3 flat and rounds as one component** — `C3AtAGlance` takes a `mode` prop (`"flat"` | `"rounds"`) rather than the legacy's two separate functions. _Same treatment, same block code; one component per block is the component-discipline rule._ → Set aside: two components (`C3flat`, `C3grouped`) — mirrors the legacy literally, but splits one block into two files.

## Publications

**62. Shared wireframe primitives over Publications-local ones** — `FilterBar`, `CountRow`, `Card`/`Cover`, `Embed` and `EmptyState` live in `components/wireframe/` because Mawred Network and News will reuse them. _One primitive per pattern; the unit that first needs a primitive owns it for the whole app._ → Set aside: Publications-local copies — faster to ship but duplicates MN3/MN4 and N1–N3 work later.

**63. `Chip` reused for removable filter chips** — active filter chips carry the `×` in the label rather than a separate `.chipx` size variant. _Decision 58 already collapsed the legacy size difference; one chip component is enough._ → Set aside: a dedicated removable-chip variant — mirrors legacy markup literally but adds a one-off size fork.

**64. `FilterBar` self-contained as a client component** — facet open/close state lives inside `FilterBar`, the same way `Accordion` owns its toggle. Page shells (`LibraryPage`, `SeriesPage`) remain the single wireframe-state boundary per decision 60. _Interactive primitives own their own UI state; the page shell only reads panel toggles._ → Set aside: lifting facet state into `LibraryPage` — one fewer `"use client"` file, but spreads interactivity up a tier.

**65. Fixed embed footprints over aspect ratios** — audio and video embeds use fixed height boxes rather than aspect-ratio utilities; the SoundCloud embed has no meaningful aspect to preserve. _Footprint difference is the wireframe signal; aspect-ratio would imply precision the provider chrome doesn't support._ → Set aside: provider-specific aspect ratios — closer to live embeds but outside the lo-fi constraint and hard to maintain across providers.

## Next.js port (continued)

**83. Page shells co-located with routes** — the 16 `<Name>Page.tsx` composition files move out of `components/blocks/<page-type>/` and sit next to the route that renders them; `page.tsx` stays a two-line wrapper. Shared shells (`ProgramPage`, `SeriesPage`) sit at the route-group level (`app/programs/`, `app/publications/`). _A shell is route composition, not a reusable block; `components/blocks/` holds blocks only, and a shell has exactly one caller so distance from the route bought nothing._ → Set aside: inlining the shell body into `page.tsx` — one file per route, but loses the named shell and forces `"use client"` onto the route file; `components/pages/<page-type>/` — clean split, but no closer to the route than before.

## Content population

**84. Content props are optional, with the placeholder as the fallback** — every prop added to carry real content (`Prose.text`, `KV.value`, `Figs` item values, and the C1/C3/C4/C5/C8/C9/C10/C12 additions) is optional, and a block given nothing renders exactly the fill bars it rendered before. _Population runs one page-type per unit over shared blocks; a required prop would force every other page-type to be populated in the same session, or hand-fed empty strings until its own turn came._ → Set aside: separate populated and unpopulated variants of each block — explicit about which is which, but doubles the block kit and breaks the one-component-per-block rule; required props with placeholders passed from config — moves the fill-bar decision into nine config files.

**85. Eligibility detail folds into C8** — the Guidelines-tab eligibility rules (re-application, who submits per discipline, under-18 documents) render as C8 items alongside the exclusions and application terms; C3 keeps only the one-line eligibility summary. _Eligibility has no block of its own, and the detail is a list of conditions — the same shape as the rest of C8. C3 is the scan-in-five-seconds table and would stop being one._ → Set aside: a new eligibility block — cleaner semantics, but re-opens structure the spec settled, for all four programmes; expanding C3 with the detail — no new block, but buries the dates the table exists to surface.

**86. Wijhat's covered-costs list goes in S4's "The grant" cell, not a C5** — the €7,000 ceiling and the five cost types it covers (tickets, visa costs, accommodation, partial living expenses, internal transport) render as a lead plus a bullet list in the page-top summary cell; Wijhat gets no C5 block. _C5 exists to set forms of support against each other, each with its own amount — with one record there is nothing to compare and the block reads as a broken table. The live page puts the list in this exact cell, and duplicating it into a C5 would reproduce the marketing-layer duplication the audit already flags._ → Set aside: a single-record C5 — gives the list its own labelled block and keeps S4 cells short, but a one-row support table isn't a support table, and the list would then appear twice on one page.

**87. The visa recommendation letter is a C6 note, placed after S5** — the provision that Culture Resource can write to the embassy once the contract is signed renders as the highlighted-note callout, immediately below the application paths. _No block owned it, and C6 is the kit's slot for exactly this: one short provision that matters more than its length. Sitting after S5 it answers the "grantees obtain their own visas" line the visitor has just read, and visas are named in C1's problem framing, so the answer belongs on the page rather than buried in contract terms._ → Set aside: a line in each S5 path — where the live page puts it, but it's stated twice there and reads as a step in applying, which it isn't; a C10 item — accurate, since it is post-signing, but it would only be found by someone already reading the contract terms.

**88. Repeating the common flow under both headings would bury the only thing a visitor is there to find — which track they're in and what it costs them._ → Set aside: reproducing each track's full flow — mirrors the live page literally, but duplicates 80% twice and makes the two paths look interchangeable.

C8 is a list of eligibility and application conditions and they would be lost in it._ → Set aside: C8 items — one fewer prop on S6, but separates the rules from the dates they qualify; C3 rows — closest to the live page's order, but decision 85 keeps C3 as the scan-in-five-seconds table and prose rules would end that.
